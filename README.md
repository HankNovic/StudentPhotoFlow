# StudentPhotoFlow｜学生照片导出与处理工具

这是一个面向 64 位 Windows 10、Windows 11 的便携式图形工具，用来读取 `.xlsx` 学生信息表，把原始照片按“学号”命名后导出，并持续记录每一批次的新增、更新、重新处理和失败状态。

本工具已按提供的样表适配：A 列为“学号”，B 列为“个人免冠照片”。样表中的照片不是内嵌图片，而是带短时签名的下载链接。工具也兼容普通 Excel 浮动内嵌图片、本地图片路径和 Data URI。

## 便携版使用方法

便携版适用于 64 位 Windows 10、Windows 11，不需要安装 Python，也不需要单独安装图片或 AI 依赖。

1. 完整解压 `StudentPhotoFlow_Windows_x64_v1.10.0.zip`。
2. 不要只复制 EXE 或 BAT；`PhotoExporter.exe`、`启动工具.bat` 和 `_internal` 文件夹必须放在一起。
3. 双击唯一的 `启动工具.bat`。也可以把 `.xlsx` 文件拖到这个 BAT 上。

启动器会自动检查内置 Python 运行时、Tkinter 图形界面、`rembg/u2netp` 和 `YuNet ONNX` 等关键文件。成功启动主程序后，黑色 BAT 窗口会立即自行关闭；只有便携包缺文件或启动命令失败时才会保留窗口显示错误。主程序自身异常会在当前目录生成 `启动错误.log`。所有组件均已包含在便携包中，首次处理不需要联网下载模型。

默认“换背景”为“不处理”。处理参数、预检阈值、Hivision 地址、裁切尺寸、输出目录、工作表和列选择等会自动保存到便携目录的 `StudentPhotoFlow.settings.json`，下次启动自动恢复；也可以点击“保存当前配置”立即保存。点击“导出配置”可生成可迁移的 JSON 配置，另一份便携版可用“导入配置”应用并保存。强制重新下载和强制重新处理属于一次性操作，不会被记住。

项目只发布和支持完整便携版；源码目录中的 `启动工具.bat` 不承担依赖安装功能。

### 从 v1.8 / v1.9 升级到 v1.10

先结束任务并关闭旧程序，备份整个旧“导出结果”目录。将新 ZIP 解压到**新的程序目录**，不要只替换 EXE。
可以在新程序选择原来的输出目录继续使用，也可以复制整个“导出结果”及 `StudentPhotoFlow.settings.json` 到新目录。
继续使用已有 JSON，不要删除状态、不必重新导入或保存全年级名单；重新保存名单会关闭归档保护开关。
本版不改变已有归档照片的存储格式，不自动恢复旧版本因强制重下载而失效的审核；这些学生在新统计中的“历史通过已失效”单列。

v1.9 修复了重下载相同照片导致重处理的问题；合并审核照片交付 / 综合名单补丁；增加结果网页全年级统计。

### 历史已交付名单锁定（v1.10）

如果以前已经给办卡人员发送过照片，可以以实际发送名单为准，不必先修复全部旧审核快照：

1. 新程序选择原有“导出结果”目录，确认其中有已校验的全年级名单。
2. 点击 **“已交付锁定…” → “导入名单…”**，选择实际已发送的学号 JSON / TXT / CSV / XLSX。旧的 `审核通过学号.txt` 可以直接使用；先核实它确实对应实际发出的照片，不要仅凭“曾导出”就锁定。
3. 确认人数，勾选已实际交付，点击 **“确认导入并锁定”**。仅追加新学号，重复导入不增加人数；名单外学号、重复或非法学号会阻止保存。
4. 后续普通/强制/网页选中重处理、断点续跑、待审核队列及所有照片交付模式均跳过锁定学号。强制下载仍可更新原图，但不会解除交付锁定，也不会触发这些学生的后续处理。
5. 在“查看最新批次”刷新全量统计。例如全年级676、导入已交付483后，显示“已交付锁定483”“剩余待交付193”。旧审核失效不会把锁定学生重新列入待办。顶部搜索仍可查看其流程，但审核按钮禁用。
6. 只处理、审核其余学生，然后使用“审核结果导出… → 新增”。新交付目录里没有历史TXT时，已锁定名单也可以作为起点；若有旧累计名单，则与锁定名单合并排除。初次导入模式同样不会导出锁定者。

**数据以 JSON 保存，逻辑复用**：`delivery_state.py` 为处理/审核/统计/独立交付共用校验模块。数据目录新增 `delivered_state.json`，保存锁定学号、校验摘要、导入来源及导入/解锁操作历史；修改前备份到 `交付锁定历史/*.json`。缺少新文件的旧数据仍可读取；新文件损坏会停止相关操作，不能静默当成没有锁定。复制迁移时请带上整个数据目录，切勿只复制旧的三份状态文件，也不要再用旧版程序处理该目录。

锁定与普通审核完全分离，不会把未经确认的新照片改成“审核通过”；关闭审核归档开关、重新保存全年级名单、改参或换照片都不会解除锁定。主界面可导出锁定JSON，可重新导入另一份便携版。

确需解除时，在同一窗口输入要解除的学号，点击“解除输入区学号的锁定…”并填写原因。解锁有确认、版本冲突检查、历史记录及备份，不会删除原图或旧审核。**解锁不会修改旧交付TXT**，因此旧累计名单仍可阻止重复交付；确需重新发送要另外核对交付基线。

每次交付附带 `综合名单.json`；照片导出还生成 `累计交付学号.json`，兼容TXT继续保留。累计导出名单不等于已实际发送；整批真正发出后，可导入该JSON并确认锁定，不会在导出时自动锁定。仅查询名单不推进交付累计记录。

命令行同样复用以上校验（无需Excel）：

```powershell
PhotoExporter.exe --import-delivered "D:\照片交付\审核通过学号.txt" --confirm-delivered --output "D:\StudentPhotoFlow\导出结果"
PhotoExporter.exe --unlock-delivered "D:\需解锁学号.json" --confirm-unlock --unlock-reason "更正误导入" --output "D:\StudentPhotoFlow\导出结果"
```

## 建议操作顺序

1. 从采集系统导出最新 Excel。
2. 立即打开本工具并选择该文件。样表链接签名只在短时间内有效；过期后无法恢复，只能重新导出 Excel。
3. 点击“检查表格”，确认工作表、表头行、学号列和图片列。
4. 点击“1. 导出原图”。这一阶段只读取 Excel、下载新增或变化的照片并按学号保存，不会执行预检、换背景或裁切。
5. 设置预检、换背景、Hivision 和裁切参数；需要调试阈值时可先打开“可视化处理工作台”。
6. 点击“2. 处理图片”。这一阶段只读取 `原始图片` 和 `export_state.json`，不访问 Excel 中的图片链接；关闭软件或移走 Excel 后仍可重新调参处理。
7. 两个阶段运行中都可点击“暂停”；已启动任务会安全收尾，点击“继续”后从当前进度接着执行。需要结束本批时点击“中断任务”，程序会保存已完成项和未完成恢复清单后停止。

如果电脑断电、进程被任务管理器结束，或运行时确认强制关闭主程序，每完成一名学生后的状态都已经原子写入 `export_state.json`。下次使用相同 Excel/列设置继续导出，或使用相同处理参数继续处理时，程序会识别中断批次，只补做未完成学号。手动点击“中断任务”会生成 `cancelled` 状态；异常强制关闭会在下次启动同一阶段时识别为 `interrupted`。批次目录的 `run_status.json` 会标明 `running`、`cancelled`、`interrupted` 或 `completed`。

## 批次网页筛选与批量操作

### 全年级综合统计与学号（v1.10）

从新主程序“查看最新批次”打开网页，顶部显示跨全部批次的统计；已有旧批次也能使用，无需为了升级重新下载或处理。
统计包含：全年级、有效已审核归档、剩余未通过、已处理但未通过、处理成功待审核、人工审核不通过、人工跳过、审核失效、历史通过已失效、机器检查不通过、处理失败、处理警告或异常、未发现处理记录、尚无导出记录、仅历史处理记录。

- 点击统计卡片或切换“学号范围”查看对应学生，支持按学号 / 原因筛选和分页。点击学号复用顶部搜索详情，查看其最新完整流程。
- “导出筛选 JSON / 学号 TXT / 明细 CSV”包含所有符合筛选的学生，而非仅当前页；也可展开全部学号直接复制。前导零用JSON字符串或TXT保留；Excel打开CSV时请将学号按文本导入。
- 全年级 = 已交付锁定 + 剩余待交付；剩余待交付 = 有效已归档（未锁定）+ 未通过（未锁定）。其余分类可交叉，不应相加；机器成功不等于人工通过，已交付也不代表当前新照片已审核通过。
- “已处理”包括失败的处理尝试。与交付脚本使用同一套统计逻辑，会补查历史批次中未写入主状态的失败项，并显示历史缺失或中断提示。
- 未锁定学生以当前有效审核为准。之前通过但图片/流程快照改变的学生计入剩余并列入“历史通过已失效”，不会自动恢复审核。锁定者单列，不重复计入待办分类。
- 统计必须有校验保存的完整年级名单。任务运行 / 暂停时无法获得一致的全量快照，会提示结束或中断后刷新；刷新失败会明确标注保留的是旧统计。
- 此面板需要主程序保持开启并通过“查看最新批次”进入；直接双击静态 HTML 只保留原有本批次功能。

### 本批次筛选与操作

- 新生成的批次网页可按学号/说明搜索，并按成功、失败、需重传、处理警告、新增、更新、修复或重新处理筛选。
- 可以全选当前筛选结果、逐项勾选或清空选择；“导出选中信息 CSV”会下载仅含所选学生的明细，可直接用 Excel 打开。
- “按已保存配置重新处理选中项”只处理勾选的学号，参数严格读取便携目录当前保存的 `StudentPhotoFlow.settings.json`，不会使用网页临时拼接参数。
- 批量重处理需要主程序保持打开，并从主程序的“查看最新批次”打开网页。程序会临时启动一个仅绑定 `127.0.0.1`、带随机报告令牌的本地服务；它不会向局域网或互联网公开学生照片。直接双击 `index.html` 时仍可筛选和导出 CSV，但不能调用本机重处理。

原图始终保持服务器返回的原始字节，不会因为开启换背景而被覆盖。处理结果单独保存在“处理后图片”目录。

## 全年级名单、逐张审核与归档

主程序新增 **“审核结果导出…”**，无需安装 Python，三种操作均直接使用当前输出目录：

- **初次导入**：把全部当前有效通过的归档照片按“学号.扩展名”平铺导出，并生成初次累计名单。
- **新增**：读取历史“审核通过学号.txt / 审核通过学号(数字).txt”，只交付新通过的学号，保存到“新增(数字)”并生成同号累计名单。
- **仅导出名单**：不复制照片，生成“已处理但未审核通过学号.txt”、分类明细、分类 TXT 及全年级剩余名单；不占用新增编号，也不改变累计交付名单。

导出时选择交付父目录，新增请选择上次的目录以便自动找历史名单；找不到或有冲突时会要求选择 TXT。
源图、审核状态和历史交付不改写；错误或中断目录不作为下次新增的依据，复制失败的照片不会加入累计名单。
图片交付、仅名单查询期间不能并行导出 / 处理或保存审核；等待结束后再操作。

命令行也已合并，例如（`--output` 是原有数据目录，`--delivery-output` 是新交付父目录）：

```powershell
PhotoExporter.exe --review-export lists --output "D:\StudentPhotoFlow\导出结果" --delivery-output "D:\名单查询"
PhotoExporter.exe --review-export initial --output "D:\StudentPhotoFlow\导出结果" --delivery-output "D:\照片交付"
PhotoExporter.exe --review-export incremental --output "D:\StudentPhotoFlow\导出结果" --delivery-output "D:\照片交付"
```

新增可另加 `--previous-delivery "D:\旧交付\审核通过学号.txt"` 指定历史累计名单。

也继续保留独立的
[`export_reviewed_photos.py`](export_reviewed_photos.py)；参见[独立导出说明](审核结果独立导出说明.md)。
它提供“初次导入”和“新增”两种模式，新增读取历史学号名单去重，并生成编号照片目录与累计名单副本。
它只读取当前审核状态，不改变已有归档结构，不依赖项目模块或第三方图片库。

1. 在主程序的“全年级名单 / 审核归档”中导入 TXT、CSV、XLSX 或粘贴学号。表格须有唯一的“学号”列，或仅一列学号；XLSX 会合并各工作表。文本学号保留前导零，不接受空名单、重复、空学号和非法字符。
2. 核对人数、确认是全年级完整名单，再点击“校验并保存名单”。程序无法从已收集照片推断全年级人数，所以必须由名单提供者确认完整性。名单保存在当前输出目录的 `grade_roster.json`，不是普通运行配置的一部分。
3. 点击“启用审核归档”。没有校验保存名单不能启用；重新保存名单会关闭开关，须重新启用，已有审核记录仍保留。
4. 从主程序“查看最新批次”进入网页，点击顶部“打开逐张审核”。旧批次也能使用新入口。保持主程序开启；直接双击静态 HTML 无法搜索全年级或修改审核状态。
5. 审核页按全年级名单顺序遍历所有已有处理记录（跨批次），默认显示待审核和图片已变化项。主要展示最终照片，顶部展示学号，下方可展开完整流程。失败无成片项只展示原图作参考，不允许通过归档。

- **是 · 通过并归档**：立即保存归档副本和审核状态。此版本在普通处理、强制处理、网页选中批量重处理时均跳过，批次中显示“已审核归档”。改参数不会解除保护。
- **返回上一张**：只导航，不修改之前的标记。
- **否 · 不通过**：记录人工审核不通过；不会自动通知学生，不归档。
- **跳过**：记录本次跳过；之后可切换“已跳过”范围继续审核。
- **撤销最近标记**：撤销当前输出目录最近一次未撤销的审核，恢复先前状态；可以逐步撤销。历史归档副本仍保留，不删除照片。

批次页和审核页顶部复用同一学号搜索框，按完整学号搜索所有导出记录，不局限本批次。批次页展示该学号最新流程详情；审核页定位该学号并可标记。名单内尚未采集的学号会提示“尚未导出”，名单外可查看但不能审核归档。原有批次内模糊筛选继续保留。

审核状态在 `review_state.json` 中逐项原子保存，副本在 `审核归档/学号/内容指纹.扩展名` 中保留。批准绑定原图、处理结果及处理记录；学生换了原图或结果版本变化后，旧批准失效，显示需重审。多页面同时审核同一版本时会检查版本和最近标记，冲突必须刷新，防止误覆盖。任务导出/处理期间可以查看网页，但须任务结束或安全中断后才能保存审核；暂停仍占用任务写锁。

备份或迁移时请复制整个输出目录，包括原图、结果、批次记录、全年级名单、审核状态和归档副本。只导出脚本配置不会携带名单、照片或审核状态。手动关闭“归档保护”后已通过照片会重新参与处理，请谨慎操作。

### 将已有归档整理成学号命名的图片

独立脚本 `归档照片转学号.py` 用来将 `审核归档/学号/内容指纹.jpg` 复制成 `审核归档_学号命名_时间/学号.jpg`。无需主程序或第三方依赖，需要 Python 3.10 及以上；不修改便携版原来的归档格式。

先结束审核并关闭照片工具，避免整理期间审核状态变化。双击脚本，选择“审核归档”（也可以选“导出结果”或便携版目录），完成后会打开新输出文件夹。图片原字节复制、保留原扩展名和学号前导零，不会压缩、换背景或覆盖原图。原文件夹和 JSON 状态保持不变。

如果旁边有 `review_state.json`，按记录中标记为通过的 `archive_file` 选择归档版本，并校验记录中的图片指纹；没有通过标记的历史副本不复制。此工具只整理归档，不重新检查当前原图是否仍符合审核要求。没有审核记录时，每个学号只有一张图片才自动复制；多个版本不会擅自取最新，而是列入 `整理记录.csv` 供人工确认。损坏的审核记录会阻止整理，不会静默降级。默认每次建立新文件夹；手动指定的目标目录必须为空，防止混入旧结果或覆盖已有照片。

也可命令行运行（路径替换为自己的目录）：

```powershell
python "归档照片转学号.py" "D:\学生照片\导出结果\审核归档"
python "归档照片转学号.py" "D:\学生照片\导出结果\审核归档" --dry-run
python "归档照片转学号.py" "D:\学生照片\导出结果\审核归档" --output "D:\本次交付照片"
```

`--dry-run` 只检查并列出计划，不创建文件。命令行退出码：0 完成，2 部分条目失败或需人工确认，1 整体未能完成。

## 增量规则

- 首次出现的学号：记为“新增”。
- 同一学号的照片对象发生变化：记为“更新”。
- 状态中已有照片但磁盘文件丢失：记为“修复”。
- 第一步只比较原图来源：来源未变且本地原图存在时记为“未变化”，不会重复下载。
- 第二步只比较处理指纹：换背景颜色、处理模式、人脸检测设置、裁切或 Hivision 参数变化时记为“重新处理”。
- 原图和处理设置都没变：第二步记为“未变化”，不会重复处理。
- 每次重新导出的签名参数会变化，但工具会忽略这些短时参数，因此不会把全部旧记录误判成更新。

如果勾选“强制重新下载已有照片”，本次所有已存在记录都会重新下载核对。v1.9 在写文件前比较新内容 SHA256、已保存指纹及磁盘原图：

- **内容相同**：记为“未变化”，保留原图文件时间、处理结果、处理配置指纹和当前审核；后续强制处理也仍跳过有效已归档项。
- **内容不同**：旧原图 / 成片移入“历史版本”，新照片等待处理，旧审核失效，须重新审核。既有“审核归档”副本仍保留。
- 下载地址改变但图片相同，也不重置处理。仅凭旧 JSON 指纹相同而磁盘文件已被改动，不会保留旧审核。

该修复防止后续误失效，不会篡改原有已经失效的审核标记。

## 输出目录

```text
导出结果/
├─ 原始图片/                 学号.原扩展名
├─ 处理后图片/               学号.jpg
├─ 历史版本/                 被更新或重新处理前的文件
├─ 批次记录/
│  └─ 批次时间/
│     ├─ 本次新增/           本批新增照片合集
│     ├─ 本次更新/
│     ├─ 本次重新处理/
│     ├─ 处理步骤/           每位学生逐步处理的中间图片
│     ├─ index.html          横向展示每一步的可视化合集
│     ├─ manifest.csv        可用 Excel 打开的完整明细
│     ├─ 需重传名单.csv      本批预检不合格名单（有不合格时生成）
│     ├─ run_status.json      运行检查点与中断状态
│     └─ batch.json          本批机器可读记录
├─ export_state.json         跨批次增量状态
└─ 查看最新批次.html
```

`export_state.json` 采用 UTF-8 JSON，保存每个学号的来源指纹、图片哈希、预检状态、退回原因、检测指标、处理引擎、输出文件、逐项恢复检查点和历次批次摘要。带签名的完整照片网址不会写入状态文件，只记录去掉签名后的地址。

## 分步骤预检与图片处理

- 内置预检使用 Pillow、OpenCV 和 YuNet ONNX，可整体关闭，也可分别启停方向、黑白、人脸、反光和翻拍检查。
- 方向修正采用正向优先的安全阈值；只有旋转候选明显优于原方向时才自动旋转，避免正常证件照被误转 180°。
- 黑白、无人脸、多人脸、严重反光和明显翻拍默认列入重传名单，并停止后续换背景。
- YuNet 仅做离线人脸检测和五官定位，不做人脸身份识别，也不建立人脸库。
- “可视化处理工作台”按顺序显示原图解码、方向、人脸、黑白、反光、翻拍和换背景结果；调整阈值后可立即整条重跑并另存图片与 JSON 参数记录。
- “快速纯色背景替换”适合原背景较均匀的证件照，速度快且无需额外模型。头发边缘复杂或背景杂乱时，建议改用 AI 模式。
- 默认不换背景。需要时可选择“AI 智能抠图换背景”，它使用便携包内置的 `rembg/u2netp`，无需联网。
- “Hivision API”仅是可选 HTTP 接入。Hivision 服务和模型不会打进便携包，只有用户主动选择该模式时才会访问填写的地址。
- Hivision 页签和可视化工作台可调 API 地址、超时、宽高、DPI、抠图模型、人脸模型、标准/高清结果、人脸对齐、面部占比、面部中心高度、头顶留白、亮度、对比度、锐化和饱和度；这些值会写入批次 JSON 和增量处理指纹。
- Hivision 参数页提供“测试 API”：只读取服务的 `openapi.json`，检查 `POST /idphoto` 和当前 16 个表单参数是否兼容，不会上传任何学生照片。
- 背景色默认标准蓝 `#438EDB`，也可选择白色、红色或自定义颜色。
- 可启用“最终图片裁切”，自定义精确像素宽高，例如 295×413；程序按人脸位置进行等比裁切后缩放，并把成片作为独立可视化步骤。

## 命令行用法

只检查表格：

```powershell
PhotoExporter.exe "学生信息.xlsx" --inspect
```

第一步，只增量导出原图：

```powershell
PhotoExporter.exe "学生信息.xlsx" --cli --output "D:\照片导出" --sheet "Sheet1" --id-column A --image-column B
```

第二步，处理已导出的原图（不再需要 Excel 参数）：

```powershell
PhotoExporter.exe --cli --operation process --output "D:\照片导出" --quality-check --background-mode quick --background-color "#438EDB"
```

同时输出 295×413 像素成片：

```powershell
PhotoExporter.exe --cli --operation process --output "D:\照片导出" --quality-check --crop --crop-width 295 --crop-height 413
```

不指定 `--background-mode` 时默认使用 `none`（不换背景）。选择可选 Hivision 服务时可使用：

```powershell
PhotoExporter.exe --cli --operation process --output "D:\照片导出" --background-mode hivision --hivision-url https://photo-api.example.com --hivision-matting-model hivision_modnet --hivision-face-model mtcnn --hivision-face-align --hivision-head-measure-ratio 0.20 --hivision-top-distance-max 0.12 --hivision-top-distance-min 0.10
```

需要 Hivision 高清返回时再加 `--hivision-hd`。运行 `PhotoExporter.exe --help` 可查看亮度、对比度、锐化、饱和度等完整参数。

只测试 Hivision API 和参数兼容性（不上传照片）：

```powershell
PhotoExporter.exe --cli --test-hivision-api --hivision-url https://photo-api.example.com
```

## 构建便携版

构建机使用 64 位 Python 3.12，在 PowerShell 中运行：

```powershell
.\build_portable.ps1
```

脚本会创建隔离构建环境，并在 `release/` 生成完整 ZIP。该目录及便携运行库不会提交到 Git。

## 注意事项

- 工作簿仅作为数据读取，不会被修改。
- 便携版目标平台为 Windows 10/11 x64，不支持 32 位 Windows 或 Windows on ARM 原生运行。
- 程序为本地自建的未签名 EXE；如果 Windows SmartScreen 首次提示，请核对文件来源后再决定是否运行。
- 照片和状态记录含个人信息，请把输出目录放在有访问控制的磁盘，不要上传公共网盘。
- 同一张表中出现重复学号时，工具会跳过所有冲突行，防止照片互相覆盖。
- 如果 `export_state.json` 被手工改坏，工具会停止，不会自动清空历史。先备份并修复该文件后再运行。
